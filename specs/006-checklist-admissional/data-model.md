# Data Model: US4 — Checklist admissional e liberação para acesso

**Feature**: `006-checklist-admissional`  
**Date**: 2026-09-27

## Existing entities affected

### Mobilizacao

Existing fields remain canonical: `Id`, `FuncionarioId`, `ContratoId`, `ObraId`, `ProcessoId`, `Funcao`, `DataFimObra`, `TurnoJornada`, `Situacao`, `CriadoEm`.

Changes in behavior:

- `Situacao` can move automatically only between `Aguardando` and `Liberado` through the release rule.
- `Afastado` and `Desmobilizado` are never promoted by document evaluation.
- Repository gains a lock-for-update read used by the transactional recalculation coordinator.
- The client never supplies `Situacao`, actor, company, worker or worksite in a release mutation.

### ItemChecklist

For `TitularTipo = Trabalhador`, `TitularId` means `Mobilizacao.Id`. A worker with two mobilizations therefore owns two independent admission checklists.

Recommended index:

```text
(TitularTipo, TitularId, Ativo)
```

Behavior by admission item:

| Code | Source of truth | Situation rule |
|------|-----------------|----------------|
| `MOB_CADASTRO` | Mobilization + worker | `Aprovado` while required parent fields are complete |
| `DOC_OFICIAL_FOTO` | Current approved document version | `Aprovado` after typed validation |
| `ESOCIAL_VINCULO` | Current approved/preliminary version | `Aprovado`, `Preliminar` or `Vencido` |
| `ASO_ADMISSIONAL` | Current approved version + analysis validity | `Aprovado` or `Vencido`; incompatible restriction blocks approval |
| `NR18_BASICA` | Current approved version + catalog validity | `Aprovado` or `Vencido` |
| `ORDEM_SERVICO` | Current approved signed version | `Aprovado` |
| `EPI_ENTREGA` | EPI movement balance | `Aprovado` only with positive active balance |
| `INTEGRACAO_OBRA` | Latest integration | `Aprovado`, `Vencido` or pending when marked to redo |
| Additional required item | Its current evidence | Must be satisfied or yields `REQUISITO_ADICIONAL_PENDENTE` |

### DocumentoVersao and AnaliseDocumento

No new table is required. `DocumentoVersao.CamposJson` stores canonical JSON after typed validation. `AnaliseDocumento.ValidoAte` stores the validity derived by the server for ASO, NR-18 and S-2190.

Approval rules:

- validate JSON syntax and mandatory fields when submitted;
- validate again against current mobilization, worker, company, role and catalog parameters during approval;
- ignore a client-selected validity when it conflicts with the derived value;
- mark S-2190 as `Preliminar`, not `Aprovado`;
- a later valid S-2200 becomes the current evidence and fulfills the link requirement.

## New entity: MovimentoEpi

Append-only event representing delivery, replacement or return.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| `Id` | UUID | yes | Generated by server |
| `MobilizacaoId` | UUID | yes | Existing mobilization |
| `ItemChecklistId` | UUID | yes | Active `EPI_ENTREGA` item for the same mobilization |
| `Tipo` | enum | yes | `Entrega`, `Substituicao`, `Devolucao` |
| `MovimentoOrigemId` | UUID | conditional | Null for delivery; active origin required for replacement/return |
| `Epi` | string(200) | yes | Trimmed, non-empty |
| `Quantidade` | integer | yes | Greater than zero |
| `NumeroCa` | string(50) | yes | Trimmed, non-empty |
| `Data` | date | yes | Cannot be after the operation date |
| `OrientacaoUso` | boolean | yes | Must be true for a delivery/replacement that fulfills release |
| `ResponsabilidadeGuarda` | boolean | yes | Must be true for a delivery/replacement that fulfills release |
| `AceiteTrabalhador` | boolean | yes | Must be true for a delivery/replacement that fulfills release |
| `RegistradoPorUsuarioId` | UUID | yes | Derived from authenticated identity |
| `IdempotencyKey` | string(100) | yes | Unique within mobilization and operation family |
| `PayloadHash` | char(64) | yes | Detects reuse of key with different content |
| `CriadoEm` | timestamp UTC | yes | Generated by server |

Relationships and indexes:

- `Mobilizacao 1 — * MovimentoEpi`, delete restricted.
- `ItemChecklist 1 — * MovimentoEpi`, delete restricted.
- `MovimentoEpi 0..1 — * MovimentoEpi` through `MovimentoOrigemId`, delete restricted.
- Index `(MobilizacaoId, CriadoEm, Id)` for chronological reads.
- Unique `(MobilizacaoId, IdempotencyKey)`.

Balance rules:

1. `Entrega` adds `Quantidade` to the active balance.
2. `Substituicao` requires an active origin and records replacement without increasing the active quantity beyond the replaced amount.
3. `Devolucao` reduces the remaining quantity of its origin and cannot exceed it.
4. Release requires at least one valid delivery in the history and total active balance greater than zero.
5. Rows are never overwritten or deleted by normal operations.

## New entity: IntegracaoObra

Internal record of a worksite induction.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| `Id` | UUID | yes | Generated by server |
| `MobilizacaoId` | UUID | yes | Existing mobilization |
| `ItemChecklistId` | UUID | yes | Active `INTEGRACAO_OBRA` item for same mobilization |
| `ObraId` | UUID | yes | Must equal current mobilization worksite |
| `DataHora` | timestamp with offset | yes | Cannot be in the future beyond accepted clock tolerance |
| `Conteudo` | string(4000) | yes | Trimmed, non-empty |
| `Instrutor` | string(200) | yes | Trimmed, non-empty |
| `Avaliacao` | string(1000) | no | Optional result/notes; must not contain clinical details |
| `AceiteTrabalhador` | boolean | yes | Must be true to fulfill requirement |
| `ValidoAte` | timestamp UTC | no | When present, greater than `DataHora` |
| `Refazer` | boolean | yes | Defaults false |
| `RefazerEm` | timestamp UTC | no | Filled when marked to redo |
| `RefazerPorUsuarioId` | UUID | no | Authenticated internal actor |
| `MotivoRefazer` | string(1000) | no | Required when `Refazer` becomes true |
| `CriadoPorUsuarioId` | UUID | yes | Authenticated Admin/Analyst |
| `IdempotencyKey` | string(100) | yes | Unique within mobilization and operation family |
| `PayloadHash` | char(64) | yes | Detects changed replay |
| `CriadoEm` | timestamp UTC | yes | Generated by server |

Relationships and indexes:

- `Mobilizacao 1 — * IntegracaoObra`, delete restricted.
- `Obra 1 — * IntegracaoObra`, delete restricted.
- `ItemChecklist 1 — * IntegracaoObra`, delete restricted.
- Index `(MobilizacaoId, DataHora DESC, Id)`.
- Unique `(MobilizacaoId, IdempotencyKey)`.

Validity rules:

- Latest accepted integration is effective.
- `Refazer = true` makes it invalid immediately.
- `ValidoAte <= evaluatedAt` makes it expired.
- A later valid integration fulfills the requirement while older rows remain history.

## Derived model: ResultadoLiberacao

| `MobilizacaoId` | UUID | Aggregate evaluated |

## Structured metadata schemas

All dates use ISO 8601 and CPF/CNPJ are normalized before comparison. JSON stored in `CamposJson` uses these logical shapes.

### DOC_OFICIAL_FOTO

- `tipoDocumento`: `RG`, `CIN` or `CNH`
- `legivel`: boolean, must be true
- `nome`: must match worker after normalization
- `cpf`: must match worker

### ESOCIAL_VINCULO

- `evento`: `S2200` or `S2190`
- `cnpjEmpregador`: must match mobilization company
- `cpfTrabalhador`: must match worker
- `funcaoCategoria`: must be compatible with mobilization role
- `dataAdmissao`: cannot be later than mobilization start/creation reference
- `situacaoVinculo`: active/valid value

### ASO_ADMISSIONAL

- worker, company and role identification matching mobilization
- risks and specific activities as non-empty lists/text
- `dataExame`, doctor name and `crm`
- `conclusao`: `Apto`, `AptoComRestricao` or `Inapto`
- restriction and `restricaoCompativel` required for `AptoComRestricao`
- signature/electronic validation
- optional `proximoExame`

Clinical exams, reports and results are not accepted as required metadata and must not be returned by release APIs.

### NR18_BASICA

- worker name, initial training marker, content, duration, date, place
- instructor, technical responsible and signature
- duration must meet `NR18_CARGA_HORARIA_INICIAL`
- validity derives from `NR18_PERIODICIDADE_MESES`

### ORDEM_SERVICO

- role/activities, risks, preventive measures, prohibitions, emergency and EPI guidance
- date and worker acknowledgement/signature

## State transitions

### Mobilizacao

```text
Aguardando --all requirements valid--> Liberado
Liberado --any requirement invalid--> Aguardando
Aguardando|Liberado --operational action outside US4--> Afastado|Desmobilizado
Afastado|Desmobilizado --admission evaluation--> unchanged
```

### ESOCIAL_VINCULO checklist item

```text
NaoEnviado -> PendenteAnalise
PendenteAnalise --valid S-2200--> Aprovado
PendenteAnalise --valid S-2190--> Preliminar
Preliminar --deadline elapsed--> Vencido
Preliminar|Vencido --new S-2200 version approved--> Aprovado
PendenteAnalise --rejected--> Rejeitado
```

### EPI checklist item

```text
NaoEnviado --first valid delivery--> Aprovado
Aprovado --active balance reaches zero--> NaoEnviado
NaoEnviado --new valid delivery--> Aprovado
```

### INTEGRACAO_OBRA checklist item

```text
NaoEnviado --valid integration--> Aprovado
Aprovado --validity elapsed--> Vencido
Aprovado --marked redo--> NaoEnviado
Vencido|NaoEnviado --new valid integration--> Aprovado
```

## Migration and compatibility

Migration name: timestamped `AddEpiEIntegracao`.

Required contents:

- create `movimentos_epi` and `integracoes_obra` with restrictive foreign keys;
- add chronological, ownership and idempotency indexes described above;
- add composite checklist index `(titular_tipo, titular_id, ativo)`;
- generate and commit migration `.Designer.cs` and update `JotaNunesFormsDbContextModelSnapshot.cs`;
- do not backfill events from files or legacy document records;
- existing mobilizations remain `Aguardando` until valid evidence exists;
- validate on an empty PostgreSQL database and on a database migrated from the current snapshot.

Production rollback must keep the additive tables after real writes. Prefer rolling back compatible application code or deploying a forward fix; running `Down` would delete compliance history.
